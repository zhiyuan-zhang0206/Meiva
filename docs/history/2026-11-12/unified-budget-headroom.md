# Unified budget headroom

Different caps were arriving as isolated warnings only when a file reached its
last ten lines. Authors needed the same view of directory slots and note length,
and needed to see the full inventory without being interrupted by unchanged debt.

We chose one report-only headroom table and a changed-only attention summary at
at most ten percent remaining, including negative remaining values. Hard limits
and their gates keep their existing owners. The complete table has no row limit;
the diagnostic display limit cannot hide budget readings. This replaces the
structure lint's file-specific near-cap warning with the same table vocabulary.

The checker stays standalone. It does not import the kernel or execute a checked
repository's pool validator, and it does not locate the user's live Vault. A pool
explicitly exports its actual limits and measurements; an explicit data snapshot
joins the same table. Missing readings remain unavailable. Automatically scanning
live pools or copying their limits into source lint was rejected because either
would obscure which workspace and authority a reported budget belongs to.

The original six locations motivated the contract; they are historical examples,
not six new rules or a reason to restore retired code-document character caps.
The current Memory pool owns its active note-character and directory limits.


## Owner and review follow-up

The Memory Arbiter's review established that the deployed Vault validator and the
Meiva scaffold had diverged: tracked/staged inventory, reserved-file handling and
the hook-owned index cap require their actual owner. Template tests therefore
prove only their explicit filesystem scope. The live owner supplies its own
fixed-index snapshot through separate Vault engineering; the consumer does not
scan it, execute its producer, or copy its gate logic.

We made missing input and incomplete scope visible, preserved provenance through
the final table and summary, and kept completeness advisory. Empty rows or a
missing index kind cannot appear complete. The owner and snapshot identifiers now
travel with each numeric row. A real permission-denial control also exposed
os.walk silently skipping an unreadable subtree; explicit error propagation keeps
that failed export distinguishable from an observed empty directory.

## Permission-control portability

The first regression control used a capability skip under privileged containers,
which both missed the denial there and grew the frozen skip-site budget. The
control now runs in a dedicated nonprivileged child and its own temporary tree;
a root caller selects a nonzero child UID, while an ordinary caller keeps its
existing UID. Setup refusal is separate from the snapshot assertion, and the
expected PermissionError must identify the blocked directory. The parent identity,
system accounts, production code, budget thresholds and skip ratchet are unchanged.
