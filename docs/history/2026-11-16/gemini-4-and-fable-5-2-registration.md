# Register Gemini 4 Carbon, Gemini 4 Hydrogen, and Claude Fable 5.2 with external harness metering normalization

Register `gemini-4-carbon`, `gemini-4-hydrogen`, and `claude-fable-5-2` in their provider plugins and the [pricing archive](../../../base/lm/pricing/pricing_catalog_archive.json), normalize external CLI model selectors onto matching catalog entries for usage pricing and non-`meiva` window lookups, and extend `scripts/model_registry/check_model_updates.py` so upstream model checks classify all three lines cleanly.

## Model registration and pricing boundaries

- **Official capability and rate ownership**: Both Google models (`1,048,576` input window, `2026-03` knowledge cutoff, `90.0s` TTFT budget, multimodal `image` / `pdf` / `audio` / `video`) and `claude-fable-5-2` (`1,000,000` input window, `128,000` max output tokens, `2026-06` cutoff, `ADAPTIVE_EFFORT`, `thinking_always_on=True`, default `high` effort, `120.0s` TTFT budget) are registered from [published rates](../../../base/lm/docs/pricing-model-rates.md) checked on `2026-11-16`. `claude-fable-5-1` sets `superseded_by="claude-fable-5-2"` while `claude-fable-5` and `claude-fable-5-1` remain spawnable so existing agent configurations never silently switch models.
- **Native `gemini-4-hydrogen` effort cap (`high`) vs. Antigravity `xhigh`**: Google documents `xhigh` for Hydrogen on the Interactions API and `agy`, and `agy models` exposes `gemini-4-hydrogen-xhigh`. However, `langchain-google-genai==4.4.2` (and `4.5.0`) validates `ChatGoogleGenerativeAI.reasoning_effort` (aliased as `thinking_level`) against `Literal["minimal", "low", "medium", "high"]`, rejecting `"xhigh"` with a Pydantic validation error before any request leaves the client. Native `ModelSpec.effort_levels` therefore caps at `("low", "medium", "high")` (default `"high"`), while Antigravity probes `xhigh` live from `agy models` and [harness catalog normalization](../../../base/agents/docs/harness/harness-models.md) strips `-xhigh` back onto `gemini-4-hydrogen` for billing and window resolution.
- **Conservative `UTC+14` promotional boundary on `gemini-4-carbon`**: Google publishes Carbon's `$2.0 / $0.10 / $10.0` per-1M launch rate "through November 30, 2026" and the `$4.0 / $0.20 / $20.0` standard rate "starting December 1, 2026" without specifying a timezone. Matching `gemini-4-argon`, the period boundary is pinned to `2026-11-30T10:00:00Z` (midnight December 1 at `UTC+14`, the earliest global calendar transition) so ambiguous-timezone traffic never under-reports spend. `gemini-4-hydrogen` has no promotional cutover and uses a single permanent `$1.50 / $0.075 / $7.50` period.

## Harness metering normalization and lossless unpriced accounting

- **Catalog-guarded selector stripping**: `resolve_harness_catalog_model(raw_model, known_ids)` returns `raw_model` unchanged when it is already an exact member of `known_ids`, then strips a trailing case-insensitive `[1m]` or Antigravity `-<effort>` suffix (`minimal` through `ultra`) only when the resulting stem exists in `known_ids`. Both `gateway` `token-usage` and `context-breakdown` apply this normalization exclusively when `(harness or "meiva") != "meiva"`.
- **Single warning per turn, lossless per-step `unpriced=1` events**: Multi-step `HarnessTurn` accounting in `log_turn_usage` passes `unpriced_already_reported=index > 0` to `UsageFields`. Every step of an uncatalogued external CLI model (such as `gpt-oss-120b-medium`) continues to emit its own `llm_usage` event with `unpriced=1` rather than dropping steps or fabricating `$0` cost, while emitting at most one `is unpriced` warning log per turn.
- **Upstream model tracker**: `SOURCES["gemini"]` includes `carbon|hydrogen` alongside `argon`, `SOURCES["claude"]` forwards `ANTHROPIC_WORKSPACE_ID` as `anthropic-workspace-id` for org-scoped Anthropic API keys, and pinned-IP DoH transport is isolated in `scripts/model_registry/doh_session.py` within file-length budgets.

## Rejected alternatives and scope boundary

- **`spawnable=False` pricing-only stubs**: Rejected because all three models are live on their official public APIs with verified parameters and rates.
- **Unconditional suffix stripping or native-runtime normalization**: Stripping `-max` without checking exact membership first would corrupt real catalog IDs such as `qwen3.8-max`, and normalizing `config_overlay.llm_model` on the built-in `meiva` runtime would weaken strict catalog validation for native agents.
- **Unrequested adjacent rate edits**: Separate observations noticed during primary-source verification (`claude-sonnet-5-5` cache-read rate and opt-in `claude-fable-5-2` fast mode) were reported separately and excluded from this change to keep scope minimal and authorized.
